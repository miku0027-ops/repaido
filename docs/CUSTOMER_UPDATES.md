# Customer updates, bookings and latency

The bell and drawer use only `/api/operations/notifications`. Local B2B prototype notices, fixed promotions, invented escrow guarantees, synthetic booking notifications and the active-booking badge multiplier are removed. An empty server inbox stays empty. Failures show a retry state, and read state changes only after an authenticated server write. A previously null `read_at` now receives a server timestamp; re-reading is idempotent. Bulk reading covers the same latest 100 messages exposed by the inbox and cannot touch another user's messages.

The drawer uses the shared native modal for focus containment, Escape, focus restoration and inert background content. Header, toolbar, filters and footer do not compete for one narrow row. Controls use the design system touch targets and colors; the inner feed owns scrolling. Dynamic viewport height and safe-area padding keep the close button and footer reachable on phones. Reduced motion, dark mode and enlarged text are supported.

Bookings share the native operations records instead of merging a separate legacy Firestore collection or recovering sample bookings on errors. Native account reads use indexed `customer_id`/`worker_id` lookups; notification reads use indexed `user_id`. SQLite has equivalent expression indexes. Firestore uses automatic single-field indexes, so this release needs no new console-created composite indexes. The carousel retains its position when the same jobs refresh. Customer arrival notices do not automatically open tracking dialogs or unlock looping task audio.

An in-memory client cache shares concurrent reads, retains successful responses briefly and invalidates after writes/account changes. `/jobs` and `/notifications` are fresh for 10 seconds; previously fetched views can display a snapshot for up to 60 seconds while revalidating. Errors are not cached. Caches have a fixed entry cap, do not use browser persistent storage, and invalidated requests cannot repopulate them. Commands continue to recheck server authorization/version/availability. Routine reads run in the background; writes retain local busy/error controls and optional nonblocking status feedback. The forced seven-second launch and centered loading illustration are removed.

`web/tests/customer-updates.browser.mjs` starts an isolated real SQLite API on port 8020 and uses Vite on 5187. It exercises booking creation, read persistence and cached reopening, then checks mobile/desktop bounds, 44-pixel targets, Escape/focus restoration, dark mode, 200% text and navigation to the actual booking. It does not change production accounts.

These changes remove global scans from customer inbox/booking reads. Very large individual account histories still need bounded server pagination/archival. Strict nearby worker discovery and legacy native marketplaces have separate indexing limits described in `HIRING_SEARCH.md`; this release is not evidence of million-user capacity. Tune Cloud Run concurrency, instance limits and any shared cache from representative load tests and Firestore read costs.
